01

One user task connects the containers.

Load once, answer several kinds of query

The command-line tool imports finite Cartesian points with schema id,x,y, then serves ID lookup, closed rectangle search, radius search and deterministic k-nearest-neighbor queries without rebuilding between commands.

A chained hash map provides the ID directory. A median-built two-dimensional KD-tree caches each subtree bounding box for pruning. Different IDs may share coordinates; distance ties are ordered by ID. A new CSV is parsed and indexed completely before it replaces the current snapshot.

02

Ownership and invalidation are part of the API.

Correctness before speed

The new KD-tree uses unique_ptr for child ownership and copy-and-swap for assignment. The hash map documents that every mutation invalidates iterators and detects stale use with an epoch. Library operations return values or exceptions instead of printing or terminating the process.

A diagnostic against the original course implementation reproduced three failures: self-assignment lost lookup state, deleting a single root left a non-empty iterator, and bulk construction counted a duplicate full key. Regression tests cover those cases plus empty data, malformed CSV, duplicate IDs, equal distances and transactional reload failure.

03

Uniform, clustered and collinear points.

Measure where pruning works

The benchmark covers 1K, 10K and 100K points across three generated distributions and three seeds. Spatial results are checked against independent scans; hash operations are compared with std::unordered_map. Both kNN paths use a bounded heap, and output materialization and stable ordering remain inside the timed work.

04

The first release is deliberately narrow.

What the project does—and does not—claim

Build instructions, fixed seeds, raw result rows, environment metadata, old-code diagnostics and a CI workflow are included in the repository. The application treats points as two-dimensional Cartesian coordinates; it is not a geographic distance engine.

The product snapshot is read-only. Container insert and erase rebuild the KD-tree transactionally and are not presented as fast online updates. The local MinGW environment lacked ASan and UBSan runtime libraries, so the validation report does not claim sanitizer coverage or prove absence of memory errors.
